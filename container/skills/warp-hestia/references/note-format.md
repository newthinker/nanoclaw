## 命名规则

笔记落在 vault 的 `Wiki/Macro/PBOC/` 下，文件名按 `period_type` 分五种：

| `period_type` | 文件名 | 例（period = `2026-06`） |
|---|---|---|
| `monthly` | `<YYYY-MM> 金融数据解读.md` | `2026-06 金融数据解读.md` |
| `q1` | `<YYYY> 一季度金融数据解读.md` | `2026 一季度金融数据解读.md` |
| `h1` | `<YYYY> 上半年金融数据解读.md` | `2026 上半年金融数据解读.md` |
| `q1_q3` | `<YYYY> 前三季度金融数据解读.md` | `2026 前三季度金融数据解读.md` |
| `annual` | `<YYYY> 全年金融数据解读.md` | `2026 全年金融数据解读.md` |

只有 `monthly` 带月份；其余四种**只取 `period` 的前四位年份**。

`prepare.py --print-name <contract>` 打印同一规则算出的文件名，SKILL.md 的 Step 3 用它取 `$N`。
**不要自己拼文件名**——拼错会让 `mode` 判断跟着错（见下面「`mode` 规则」）。

## 🔴 两级校验：分段 `check` + 封条 `seal`

`verify.py` 在写回前重算这两级并与文件里的值比对，任一不符即**拒绝写回**。
两级的分工是**互补**的：`check` 防「改内容」，`seal` 防「删内容」。

### ① 分段 check `<!-- check: <sha256> -->`

- **位置**：紧跟一张数据表之后。
- **作用域**：从**上一个 `## ` 标题行**（含该行）起，到本 check 行之前（不含本行）的全部文本。
- **条数**：机器区内**恰好 2 条**——`## 本期数据` 与 `## 前 12 期` 各一条。
- 🔴 **`## 信号` / `## 趋势` / `## 社融增量结构` 三段都不发 check 行**。**不要按 `## ` 标题数去推
  check 行数**：机器区有 5 个 `## ` 而只有 2 条 check，「标题数 == check 数」这个判据装反了，
  会把一份完全合规的笔记判红。**条数写死为 2，不从文档结构推。**
  📌 2026-09-16 加图表段时这个差距从「3 比 2」变成「5 比 2」——**判据没变，正说明写死是对的**：
  当初若按标题数推，这次加两段就会静默要求 4 条 check 而实际仍是 2 条。
- ⚠️ **`## ` 的计数有两个口径，都对，但都不能用来推 check 行数**：
  **机器区内**（`<!-- machine-generated: begin -->` → `end` 之间）是 **5** 个（`## 本期数据` / `## 前 12 期` / `## 信号` / `## 趋势` / `## 社融增量结构`）；**整份骨架**是 **6** 个（再加区外的 `## 我的批注`）。
  而 check 恒为 **2**。⇒ 按机器区口径推得 5、按全文口径推得 6，**两个都错，后者错得更远**。
  这正是「写死条数」而不是「从结构推」的理由。

### ② 封条 seal `<!-- seal: <sha256> -->`

- **位置**：`<!-- machine-generated: end -->` **紧邻其上**。
  🔴 **这是一条会被校验的形状要求，不只是排版约定**（M3 的 TASK-005 返工，F3）：
  `verify.py` 断言 **seal 行的下一行必须就是 `<!-- machine-generated: end -->`**，
  中间夹任何内容（哪怕一行空白）即判被篡改。
  理由：封条的作用域到 seal 行**之前**为止 ⇒ seal 与 end 之间的文本**既不被任何分段 check 覆盖、
  也不被封条覆盖**，可以在**机器区内部**插入一张伪造数据表而校验放行（实测 `verify.py` exit 0）。
  它比 frontmatter 盲区更危险：读者看到的是一张**位于机器区里**的表，比 frontmatter 更像「机器产的」。
- **条数**：**恰好 1 条**。
- **作用域**：从 `<!-- machine-generated: begin -->` 的**下一行**起、到本 seal 行**之前**的全部文本，
  **扣除** `<!-- narrative -->` 与 `<!-- /narrative -->` 之间的全部文本（**含这两行本身**）。

**封条防的是分段 check 防不住的两类篡改**：

| 篡改手法 | 分段 check | 封条 seal |
|---|---|---|
| 改一张表里的数字 | ✅ 拦下 | ✅ 拦下 |
| **删掉一条 check 行** | ❌ 没了就不比对了 | ✅ 覆盖文本变了 |
| **删掉一整段**（标题 + 表 + check 行） | ❌ 剩下的段各自仍自洽 | ✅ 覆盖文本变了 |
| **在 seal 与 end 之间插入伪造表** | ❌ 不在任何 check 的作用域内 | ❌ **也不在封条作用域内**（到 seal 行之前为止）⇒ 靠上面那条**形状断言**拦下 |
| **改 `## 信号` 段**（无 check 保护） | ❌ 不在任何 check 作用域内 | ✅ 覆盖文本变了 |

**narrative 段被扣除**，所以模型在叙述里写 `## ` 标题、写表格、随便改自己那一段，
都不会影响封条 —— 这正是 `methodology.md` 的八问框架允许你在叙述里用小标题的前提。

## 图表（2026-09-16 追加）

三段图表**全部由 `prepare.py` 生成**，模型不得改（同 frontmatter，依 ADR-0003 决策 4）。

**渲染分工**：趋势用 mermaid 折线（看得出拐点），阈值对比用文本条（永不会坏、`git diff` 干净、
在任何 markdown 阅读器里都一样）。Obsidian 1.12 内置 mermaid 且支持 `xychart-beta`，**不需要
Charts 插件**；vault 也未安装它。

| 段 | 形态 | 内容 |
|---|---|---|
| `## 信号` 内的达成度条 | 文本条 | 四信号各一行：值 / 条 / 达成度 / 阈值 / 灯 |
| `## 趋势` | 3 张 mermaid `xychart-beta` | 剪刀差、住户中长期月均、住户短期月均 |
| `## 社融增量结构` | 文本条 | 各分项占社融增量总量的比例，降序 |

**四条实现纪律**（都有测试钉住）：

1. 🔴 **不发 check 行，靠封条保护**。上面两级校验表里「改 `## 信号` 段（无 check 保护）」那一行
   已说明 seal 覆盖机器区减叙述段，改内容与删整段都拦得住。`test_verify_rejects_a_tampered_chart`
   实证到 `verify.py` 这一层，不只是写在文档里。
2. 🔴 **本期必须补在序列末尾**。侧车的 `same_type` 来自 `Store.Preceding`，语义是「period < 本期」，
   只有历史没有当期；不补的话图上看不到最新那个点，而那正是读者最关心的。
3. 🔴 **取不到值的期次跳过，不补零**。`monthly_average` 缺值时返回 `(0, False)` —— 判的是**第二个
   返回值 `ok`**，不是 `v is None`。只判 v 会把「这期没数据」画成 0，在折线上造出一个**假的谷底**，
   而读者无从分辨它和「这期真的是 0」。实测：2023-08 那份侧车有 5 个期次两个口径都缺。
4. 🔴 **两条线不画在一张图上**。`xychart-beta` **没有图例**，同图两条线无法分辨哪条是哪条 ⇒
   住户中长期与短期各占一张单线图。宁可两张图，也不要一张看不懂的。

**达成度的语义**（`achievement()`）：绿灯即 1.0；红灯也按距绿灯的远近给值，**不一律记 0**——
楼市 368.67 / 2000 = 18% 比「0%」有用得多。四个信号判定形状不同，统一成一个可比的数：

| 信号 | 形状 | 达成度 |
|---|---|---|
| 活化 | 两条线（沉淀 / 活化） | 区间内按线性位置 |
| 楼市 | 一条正阈值 | 值 ÷ 阈值，截断到 [0,1] |
| 消费 | 阈值是 **0** | 非此即彼（该信号本就没有黄灯） |
| 信贷 | 两条线（健康 / 严重） | 越小越好，反向线性 |

⚠️ **文本条按显示列宽补齐**（`pad()`，用 `unicodedata.east_asian_width`）：中文占 2 列，
`%-Ns` 按字符数补齐会让列参差，而文本条的全部价值就是一眼扫过去。超宽**不截断**——
截断会把「未贴现承兑汇票」砍成半个词，比不对齐更糟。

## `mode` 规则

- vault 的 `Wiki/Macro/PBOC/` 里**已有同名文件** ⇒ `update`（`prepare.py --existing <旧笔记>`
  已把「## 我的批注」之后的全部文本原样拼到新内容末尾）。
- **没有同名文件** ⇒ `create`。

`update` 时机器区整体重写、**批注区原样保留**；找不到 `## 我的批注` 标题则视为批注为空。

## 修订

契约 `is_revision: true` 时，frontmatter 会多一个 `supersedes_published_at`。
此时在正文一级标题（`# …金融统计数据解读`）**下面加一行**：

```markdown
> 本文取代 <supersedes_published_at 的日期> 版本。
```

这一行由 `prepare.py` 生成，模型不写、不删。
